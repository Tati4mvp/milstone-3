The Evolution of AI and Robotics

How trial-and-error learning turns robot-arm actions into skills

Code 
library(ggplot2)
library(dplyr)
library(scales)

set.seed(2026)

# This is a reproducible illustration, not a download of the benchmark data.
task_info <- tibble::tibble(
  task = c("Push", "Pick and place", "Slide", "Grasp"),
  difficulty = c(0.63, 0.48, 0.56, 0.38),
  color = c("#E76F51", "#2A9D8F", "#F4A261", "#264653")
)

evolution_stages <- tibble::tibble(
  stage = 1:4,
  title = c("Human instructions", "Simulation", "AI policy", "Robot skill"),
  detail = c("Rules written by people", "Safe practice world", "Learns from outcomes", "Acts in the world"),
  color = c("#264653", "#2A9D8F", "#E9C46A", "#E76F51")
)

episodes <- tidyr::crossing(
  task = task_info$task,
  attempt = 1:120
) |>
  left_join(task_info, by = "task") |>
  mutate(
    learning = 0.18 * log1p(attempt) / log(121),
    probability = pmin(0.96, difficulty + learning),
    success = rbinom(n(), size = 1, prob = probability)
  )

task_summary <- episodes |>
  group_by(task, color) |>
  summarise(
    successes = sum(success),
    trials = n(),
    success_rate = successes / trials,
    standard_error = sqrt(success_rate * (1 - success_rate) / trials),
    .groups = "drop"
  ) |>
  mutate(
    lower = pmax(0, success_rate - 1.96 * standard_error),
    upper = pmin(1, success_rate + 1.96 * standard_error)
  )

learning_curve <- episodes |>
  mutate(window = ((attempt - 1) %/% 10) * 10 + 10) |>
  group_by(task, color, window) |>
  summarise(success_rate = mean(success), .groups = "drop")

plot_theme <- theme_minimal(base_size = 13) +
  theme(
    plot.title = element_text(face = "bold", size = 17, color = "#17324D"),
    plot.subtitle = element_text(color = "#496579"),
    axis.title = element_text(face = "bold", color = "#17324D"),
    axis.text = element_text(color = "#496579"),
    panel.grid.minor = element_blank(),
    panel.grid.major.x = element_blank(),
    legend.position = "none",
    plot.margin = margin(12, 18, 12, 12)
  )

From programmed motion to learned skill

Robotics data often arrives as a simulation environment rather than a rectangular table. Each episode can contain observations, actions, rewards, and a final success signal. That makes the first useful question: what does one episode look like, and how should success be summarized?

The OpenAI Fetch and Hand environments are a promising setting for that question. They include robot-arm behaviors such as pushing and grasping, which makes them useful for studying a major shift in robotics: moving from instructions written entirely by people toward AI policies that improve through repeated attempts.

The figures below are a synthetic demonstration because the repository does not yet contain episode-level Fetch or Hand data. The structure mirrors the kind of summary we could make after loading real simulation episodes.

Which tasks are succeeding?

  labs(
    title = "Different robot skills evolve at different speeds",

This view is useful for comparing behaviors, but it hides when the successes happened. A robot that succeeds only after many failed attempts tells a different story from one that succeeds immediately.

The upward pattern is the visual story of AI and robotics evolution: experience can turn uncertain actions into more reliable behavior. With the actual dataset, the next step would be to replace episodes with a table created from the environment logs, then compare success by task, seed, and training method.

What this makes me wonder

It is remarkable that an AI policy can turn trial and error into physical skill. This is the larger evolution: robotics supplies the body, AI supplies an adaptable decision-maker, and simulation supplies a place to learn safely. But the same progress raises a human question: as robots take on more tasks, how will our work change, and what new kinds of work will we choose to do? A good final project can hold both ideas at once: measure what the robot learns, and ask what that learning means for people.

NoteData note

The plotted values are simulated with a fixed seed for demonstration. They should not be reported as findings about the OpenAI benchmark. For a final analysis, document the exact environment version, task definition, number of episodes, random seeds, and success metric.
